# يارب استرها

محاكاة قيادة وتفادي حوادث في مدينة ثلاثية الأبعاد. الهدف النهائي هو **مساعدة السائق على منع الحوادث المفاجئة في الشوارع المصرية**. القيادة الذاتية الحالية تخدم تجربة المسارات والمواقف داخل اللعبة.

## التشغيل

تحتاج Python 3 ومتصفحًا يدعم WebGL. لا تحتاج حزم إضافية للتشغيل:

```bash
python -m backend.server
```

افتح `http://127.0.0.1:8000/`. الأسهم للقيادة اليدوية، وزر `ENABLE AI` للقيادة التلقائية. زر الكاميرا يبدّل بين رؤية السائق الكاملة والرؤية الخلفية. `ROUTE` يعرض خط الطريق وبيانات A*، و`SENSORS` يعرض أشعة الاستشعار.

**التليفون داخل اللعبة** يظهر من زر `📱 التليفون` على الجانب. اكتب مثلًا `روح السوق` أو `اذهب إلى المستشفى`. الأماكن الحالية: وسط البلد، السوق، المحطة، المستشفى، الجامعة، الكورنيش. العربية تخطط طريقًا عبر الشوارع، تشغّل القيادة التلقائية، وتتوقف عند الوصول. لافتات بأسماء الأماكن موجودة في المدينة. هذه مطابقة أسماء بسيطة، وليست نموذج NLP مدربًا بعد.

## الموجود في هذه المرحلة

- العربية تبدأ في حارة على الطريق؛ A* يخطط بين عقد الشوارع، والحركة التلقائية تُقيّد داخل حدود الطرق. وصف الشوارع في `src/simulation/road-lanes.js`: مسافات غير متساوية، شوارع فرعية قصيرة، وعرض مختلف لبعض الطرق.
- زحمة سيارات وتكاتك بموديلات GLB مختلفة، مع شكل احتياطي للتوكتوك قابل لتعديل أجزائه في `src/simulation/traffic.js`. أغلب حركة المرور لا تلتزم بالإشارات، وسرعات العربيات تختلف، وبعضها يمشي عكس الحارة أو ينحرف داخلها. المشاة يمشون بجانب الطرق ويعبرونها في أوقات مختلفة بموديلات GLB. المباني ومصابيح الشارع من موديلات GLB، والمدينة تتمدد مع التقدم.
- سبعة أشعة raycasting، وفرملة تراقب مكان وسرعة المشاة والعربيات المتحركة خلال أفق قصير، مع فحص للحركة قبل كل خطوة. حركة الشخصيات نفسها تمنع التداخل مع عربية اللاعب. هذه قواعد محاكاة أولية وليست computer vision أو ضمان أمان لعربية حقيقية.
- كاميرا أمامية صغيرة لمراقبة ما تراه العربية، مع إمكانية عرض رؤية السائق كاملة بزر الكاميرا.
- خادم Python محلي يستقبل حالة المحاكاة وإطار JPEG من الكاميرا، لتوصيل CV وRL في الخطوة القادمة.

## ترتيب المشروع

| المجلد أو الملف | الغرض |
| --- | --- |
| `index.html`, `src/ui/` | الواجهة والتليفون الداخلي ولوحة A* |
| `src/main.js` | تركيب الوحدات ودورة اللعبة والقيادة الحالية |
| `src/simulation/` | المسارات، الأماكن، المرور، الحساسات، حدود الطريق، الفرملة، وربط Python |
| `src/render/` | المدينة والموديلات واللافتات |
| `assets/models/` | موديلات GLB وخاماتها؛ راجع `assets/LICENSES.md` |
| `backend/server.py` | خادم اللعبة وواجهة قراءة الحالة والكاميرا |
| `tests/` | اختبارات المسارات والـAPI والمنطق الأساسي |

## واجهة Python الحالية

- `GET /api/health`: فحص السيرفر.
- `GET /api/state`: آخر observation للعربية، وتشمل السرعة والوقود والوضع والموقع والحساسات والإشارة والمكان المطلوب وحالة الفرملة، إضافة إلى المشاة والمركبات القريبة بمواقعهم وسرعاتهم وأنواعهم. هذا تجهيز لتجارب الـRL القادمة.
- `GET /api/frame`: آخر صورة JPEG من الكاميرا الأمامية.

المتصفح يرسل الحالة والصورة إلى نفس السيرفر عبر `POST /api/state` و`POST /api/frame`. التليفون الداخلي يعمل في المتصفح ولا يحتاج API أو تليفونًا حقيقيًا. يمكن تشغيل اللعبة بخادم ملفات عادي؛ عندها تستمر اللعبة بدون بث الحالة إلى Python.

## التطوير القادم

1. جعل سيناريوهات الخطر الحالية قابلة لإعادة التشغيل ببذرة ثابتة وحالات اختبار صعبة للمشاة والتكاتك وقطع الطريق.
2. توصيل كاشف أجسام ورؤية كاميرا فعلية في Python، مع قياس التأخير وأخطاء الكشف. أشعة المحاكاة الحالية تبقى كمرجع منفصل.
3. إضافة OCR للّافتات وNLP للأوامر العربية. مطابقة أسماء الأماكن الحالية نقطة بداية قابلة للاستبدال.
4. تعريف observation/action/reward للتعلّم المعزز، تدريب سياسة داخل المحاكاة، ومقارنتها بخط الأساس. تبقى طبقة الفرملة مستقلة عن مخرجات السياسة.
5. تحسين فيزياء الحركة وقواعد التقاطعات والتقييم على عدد الحوادث والقرب منها، قبل أي ادعاء بأن النظام موثوق.

كل الموديلات الخارجية المستخدمة [CC0](assets/LICENSES.md)، ويمكن تعديل ملفات GLB في Blender مع الحفاظ على ملفات الخامات. صيغة العربية الحالية لا ترسل أوامر غير معروفة للقيادة.
